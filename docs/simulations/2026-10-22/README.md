及四个原身份从首页重新进入。嵌套步骤按开始编号；时间戳日志保留实际完成顺序。

Morgan 的第五次发布来自 Robin 离线后的职责交接，发现者仍记为 Robin。
这些是服务端保存的操作数，**不是发言质量或自然参与均衡的评分**。
修复后再次执行得到相同的贡献分配、16 条发布、7 项成立推理和 10 次保存尝试。

- 共发布 16 条证据，7 项推理成立，保存 10 次推理尝试：7 次成立、3 次有意错误。
- 只引用一条证据时，页面给出指引且没有发出 claim 请求，不计入保存的尝试数。
- 猜对答案但引用 G2/G4 仍被驳回；错误的相机时间也不能成立。
- 三条讨论笔记明确带有 `[Scripted simulation]` 标记；用过一次第一级提示。
- 私人发现只发给持有相应职责的身份；交接后可由接手者共享。
- 两个同时发出的时间线修改使用相同版本号，响应分别为 200 和 409；冲突方刷新后
  显示与服务器相同的顺序，没有静默覆盖。
- 不正确的最终顺序收到 400；修改顺序后，四人看到同一结局并能重新打开。
- 本轮记录 66 个修改请求响应：64 次成功，2 次有意触发的拒绝（400、409）。
  错误假设的 HTTP 响应为 200，因为服务器成功保存了一次被逻辑驳回的推理尝试。
- 未捕获浏览器 JavaScript 异常。脚本约 27.6 秒的运行时间只代表自动执行，
  完全不能用来判断目标 20–30 分钟是否合理。

## 发现并修复的问题

**P2：结案画面保留已过时的错误提示。**

触发：A 的时间线修改与 B 冲突，A 得到“未保存、已刷新”的提示；之后其他玩家完成
排序并结案。A 收到了结案状态，但旧警告仍显示在成功结局上方。
[修复前截图](screenshots/before-stale-warning.png) 保留这个矛盾状态。

原因是错误只在该玩家开始下一次修改时清空，共享结案不会清空。修复在接收服务器
确认的 solved 状态后清除旧编辑警告；开放案件中的冲突提示仍保留。
新增双人回归先让 B 提交错误重建，再让 A 成功结案，要求 B 的警告消失。
四人模拟也增加相同的结案检查。这个修正已加入现有 CI 浏览器套件。
[修复后截图](screenshots/after-clean-conclusion.png) 显示同一类结案画面已不再有旧警告。

此问题来自截图复查，而最初 63 步断言全部通过；这说明仅统计测试通过数不能代表
所有可见状态都正确。两个脚本定位错误与这个网站缺陷分开记录，没有隐藏中断轮次。

## 本轮不能替代的判断

当前证据支持多人的完整操作链、错误反馈、权限、共享和恢复行为。未观察到阻断
通关的问题；不能因此承诺不存在其他缺陷。以下仍需首次真人试玩：

1. 四人是否会自发交换信息，而不是由一个人包办推理。
2. 3D 是否帮助理解场景，还是大家更愿意只读对象列表。
3. 阅读量、提示强度、卡点与实际时长是否适合朋友或家庭聚会。

继续使用 [真人观察方案](../../playtest-protocol.md) 记录真实行为。不要把本报告改写成
“四位同学/家人试玩后认为有趣”，也不要为模拟昵称添加虚构评价。
